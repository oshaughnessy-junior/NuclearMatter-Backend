# Dev log — 2026-10-14 — GM☉/c² is the IAU nominal value

**Who:** R. O'Shaughnessy (with AI pair).  From Q2C PR #47's adversarial review
(finding F5).  It is kept separate from the tidal-c_s² fix (PR #44, devlog
2026-10-14-tidal-cs2) because it moves every mass.  Revised after the
adversarial review of PR #45 (F1–F5 below).

## Defect
`constants.py` had `MSUN_SI = 1.98892e30` kg and computed
`GMSUN_KM = G_SI * MSUN_SI / c²`.
- 1.98892e30 kg is old LAL's solar mass, meant for CODATA-1986 G (6.67259e-11),
  with which it gives GM = 1.3271248e20.
- It was paired here with CODATA-2018 G = 6.67430e-11.
- That gives **GMSUN_KM = 1.4770039 km**, 2.566e-4 above the IAU 2015
  Resolution B3 nominal (GM)☉/c² = 1.476625038 km.
- The comment beside it quoted 1.476625 km.
- It came in with the initial scaffold commit, with no source note.

The nominal value is used by:
- current LALSuite: in lal 7.7.0 `include/lal/LALConstants.h`, `LAL_GMSUN_SI` =
  1.3271244e20 ("Nominal solar mass parameter"), `LAL_MSUN_SI` =
  1.98840987069805e30 and `LAL_MRSUN_SI` = 1476.625038 m;
- RIFT, through LALSuite;
- the Q2C TOV oracle (`MSUN_KM = 1.476625`);
- nmbackend's own `cooling.runner` (`_GM_SUN_C2_CM = 1.4766250e5`).

Older LAL used the measured TDB value GM = 1.32712442099e20, which gives
`MSUN_SI` 1.988409902e30 and `MRSUN_SI` 1476.62506 m.  Those are off the nominal
values by 1.6e-8 and 1.5e-8.  The first version of this PR wrongly quoted them as
"LAL" (review F2).

## Fix
- `GM_SUN_SI = 1.3271244e20` m³ s⁻², exact by definition.
- `GMSUN_KM = GM_SUN_SI / c² / 1e3` = 1.476625038 km.
- `MSUN_SI = GM_SUN_SI / G_SI` = 1.98840987069805e30 kg.  Both agree with lal 7.7.0
  to 2e-16.  `G_SI * MSUN_SI == GM_SUN_SI` holds, and the RIFT adapter's kg → M☉
  conversion uses it.
- `postmerger.GMSUN_KM` was a separate rounded 1.4766 "G Msun / c^2 in km" (not
  a fit constant).  It shadowed `constants.GMSUN_KM` through `__all__`.  It is now
  the package constant, imported and re-exported.  Its compactness moves by
  1.7e-5, well inside the postmerger tests' tolerances (review F5).  The
  package constant is the right one for the postmerger fits: they take M_max in
  nmbackend's M☉, so GMSUN_KM·M_max/R equals the physical compactness
  M_km/R_km only when GMSUN_KM is the same constant that converted M_km to M☉.
- `tests/test_units.py::test_gmsun_km_is_iau_nominal` checks the lal 7.7.0
  values to 1e-12.  That separates them from both the old LAL values (1.5e-8) and
  the old nmbackend value.  The test fails on main.

## Effect
A star of given h_c is unchanged in km.  It is 2.566e-4 heavier in M☉: every
mass ratio is exactly 1.000257, and every M-R-Λ relation in M☉ moves.  On the 18
tables of devlog 2026-10-14-tidal-cs2 (direct M = 1.4 root), on main:
- Mmax: +2.57e-4 on every table.
- Λ1.4: +1.5e-3 to +1.8e-3 (MetaModel +1.47e-3, GM1 +1.55e-3, SLy +1.71e-3).
  The family path moves by the same amount.
- R1.4: −0.1 to +0.6 m.
- The same shifts hold on top of PR #44 to 1e-5.

## The ejecta pins (review F1)
`tests/test_ejecta.py::test_asymmetric_pinned_anchors` pins nine self-computed
values.  It specified its star by radius (R = 11.5, 12.0 km), and the fits use
the compactness C = GM☉ m/(R c²).  Four of the nine pins therefore moved with
the constant:

| pin | relative change |
|---|---|
| radice2018_mej | −4.91e-4 |
| radice2018_vej | −3.79e-4 |
| kf2020_mdyn | +9.6e-5 |
| kf2020_mdisk | +1.59e-3 |

The first version of this PR reported only the first, because pytest stops at
the first failed assert.
- The fits carry no published calibration to preserve.  They are expressed in
  C, and the production path forms C = M_km/R_km, which does not depend on the
  constant.
- The test now gives its star by compactness instead:
  `r = GMSUN_KM·m/C`, with C1 = 0.19265267846681078 and C2 = 0.1415462040401985
  (the compactnesses the pins were computed at).
- All nine pins are unchanged and reproduce, and the test no longer depends on
  the constant.
- The ejecta code is unchanged.
