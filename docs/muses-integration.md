# MUSES integration — findings & cross-code path

*Research note, 2026-06-02.  Source: MUSES 1.10 docs (musesframework.io), CMF
module repo gitlab.com/nsf-muses/module-cmf/cmf, Cruz-Camacho et al. arXiv:2409.06837,
Dexheimer & Schramm ApJ 683 (2008) 943 / PRC 81 (2010) 045201, Papazoglou et al.
PRC 59 (1999) 411.*

## What the MUSES "RMF code" actually is

The MUSES `cmf_solver` is the **Chiral Mean Field (CMF) model** — a non-linear
realization of the **SU(3) σ-model** (Dexheimer–Schramm), *not* a σ-ω-ρ Walecka RMF.
Its mesons are σ, ζ, δ, ω, φ, ρ; most baryon masses are **generated by the medium**
(they drop at high density via the chiral fields), and it includes the full baryon
octet **and** decuplet, **hyperons**, **quarks**, and a **Polyakov-loop** order
parameter for deconfinement. It is implemented in C++ (CMF++), solved with a MINPACK
multidimensional root solver over the seven mean fields, and — importantly — it is
parameterized by **chemical potentials** (μ_B, μ_S, μ_Q), i.e. grand-canonical, which
is exactly the "use the chemical potential as the parameter" framing.

**Consequence for us:** CMF is a *different and much richer* model than our σ-ω-ρ
`RMFTEOS`. Its couplings (below) do **not** map onto our (b, c) self-couplings, so
they do **not** resolve the earlier NL3 conversion issue — that remains a separate
"verify a standard linear-RMF set against its saturation point" task (see backlog).
Re-implementing CMF is a large undertaking (chiral mass generation + hyperons +
quarks + Polyakov loop) and is **not** the right use of effort here.

## The right integration: CMF as an external EOS provider

CMF emits **CompOSE-compatible CSV** tables (`CMF_output_stable.csv`,
`CMF_output_for_Lepton_*.csv`). The relevant 1-based columns are
**5 = baryon density [1/fm³], 8 = energy density [MeV/fm³], 9 = pressure [MeV/fm³]**.
So the path is: run CMF (Docker / MUSES Calculation Engine API) for the cold
β-equilibrium NS line (via its Lepton/Synthesis output) → **ingest the CSV** →
diagnose and solve:

```python
from nmbackend.eos import load_cmf
from nmbackend.validation import model_diagnostic
from nmbackend.tov import build_family, m_max, radius_of_mass

cmf = load_cmf("CMF_output_for_Lepton_baryons.csv")   # -> EOSTable
model_diagnostic(rmft_table, cmf, label_a="RMFT", label_b="CMF")   # EOS-level cross-code
fam = build_family(cmf); m_max(fam); radius_of_mass(fam, 1.4)      # TOV
```

`eos/compose.py::read_cmf_csv` (column-mapped, validated by a synthetic round-trip)
does the ingestion; `validation/model_diagnostic` gives the **EOS-level** cross-code
comparison (ε, p, μ, c_s² vs density — not just M-R-Λ), which is the diagnostic
asked for. Cross-checking a CMF table this way needs no reimplementation.

## Getting a real CMF table (for the user)

- Docker: `docker pull registry.gitlab.com/nsf-muses/module-cmf/cmf:v1.0.0`, or
  `git clone https://gitlab.com/nsf-muses/module-cmf/cmf && bash build_docker.sh`,
  then `bash run_docker_default.sh` (the MUSES Docker stack is available here per the
  earlier note; outputs land in `cmf/output/`).
- Or the MUSES Calculation Engine API (CMF++ is the first tutorial example).
- For the NS EOS specifically, use the **Lepton** + **Synthesis** module outputs
  (β-equilibrium with leptons along the NS line), not the bare baryonic grid.
- Lead developer (couplings questions): Nikolas Cruz-Camacho, cnc6@illinois.edu.

## CMF default couplings (for reference / a future chiral implementation)

From the default `config.yaml` (C4 vector scheme), MeV where dimensionful:

- Vector nucleon: gN_ω = 11.90, gN_ρ = 4.03, gN_φ = 0, **g₄ = 38.90** (vector
  self-coupling).
- Scalar nucleon (chiral): gN_σ = −10.5668, gN_ζ = 0.467039, α_X = 1.44833948.
- Scalar potential: k₀ = 2.37322, k₁ = 1.40, k₂ = −5.54911, k₃ = −2.65242.
- Decay constants / χ: f_π = 93.30, f_K = 122.0, χ_vac = 401.9338.
- Meson masses: m_ω = 780.563, m_φ = 1019, m_ρ = 761.063; nucleon_vac = 937.243.
- Polyakov: a₁ = −0.001443, a₃ = −0.396, T₀ = 200 (crossover) / 270 (pure glue).

If we ever want CMF *natively* (differentiable, in-loop), this is the parameter set
to target; until then, ingest its tables.
